# Step 6a-c-1 — scoped Store reads and installation preparation

The installed catalog and Store projection use one current ownership selector. Personal Own/Shared, an explicitly selected readable team, organization and read-only system resources retain their actual resource references. Browse authority is independent of target creation and management authority. An unavailable or omitted team never becomes personal scope.

Store discovery retains safe installed metadata during a registry outage. Offering search and installed-row search are independent of the scope-wide verified installation correlation, so a renamed display label cannot turn an existing exact installation into an apparently uninstalled offering. Installed pagination supports more than fifty resources; the single thirty-two-resource provenance budget prioritizes the selected page and excludes built-in system/core packages. Unknown and partial comparison coverage remains explicit. A final current scope/resource read removes revoked rows and invalidates stale metadata, grants and artifact observations.

Three shared read operations support the focused UI and agent workflow:

| Operation | Contract |
| --- | --- |
| Installed package presentation | Current exact Read, including parent Read for contained skills; safe declarations, child metadata, script descriptions and declared configuration key names. No executable body or credential/configuration values. |
| Store offering presentation | Exact configured kind/registry/entry/version/checksum; complete bounded verified archive before projecting declarations. No installation, publication or script/provider execution. |
| Installation options | Explicit target ownership, current target Manage before namespace/directory access; bounded active organization user/team/project targets and safe ownership labels. Does not fetch the Store or change resources, grants, drafts or preferences. |

Contained skills retain their own workflow groups. Applicable parent legacy connection requirements identify their plugin declaration; declared ENV names are a safe union. A presentation describes requirements and does not establish connection readiness, select an account or grant execution authority.

Web and Mobile use thin handlers for the same actions. Agent tools bind the actual server-issued user, agent, session and workspace context, reject caller-supplied actors/owners/paths, and return the same safe resource error codes as HTTP. The installed presentation and installation options are on the read-only Planning whitelist. Store archive preview is excluded. The effective progressive Planning gateway remains a separate step 6b requirement.
