# Shared Composio desktop API and client: step 6b-d-2c-2

The server gate is committed at `7589ffb6c`. This gate connects it to authenticated HTTP, the actual shared connection editor and Electron. Actual system-browser consent remains the following gate, 6b-d-2c-3. The gateway stays default-off; no containers or external deployments are part of this step.

1. Capture one actual human Better Auth session for desktop requests. Start accepts only desktop=true, one canonical intent and the three original revisions. Status is read-only by state or intent. Finalize and Cancel require the same original session, current Manage permission and exact connection/workspace. Only the exact static public callback bypasses session middleware. Missing Secrets return the established settings link without provider details.
2. Make Cancel conclusive before the start response is known. Under the same resource/session/profile locks, an intent cancellation either cancels its existing flow, proves its already completed publication, or stores a durable cancellation marker with the original revisions. A late queued start observes that marker and performs no provider request. A missing GET alone never proves cancellation. Markers contain hashes, references and revisions, no credentials or fake encrypted snapshot; they remain until resource deletion so late requests cannot revive them.
3. Add a privately issued Composio client handle before the first request. Capability detection precedes mutation. Every await checks the captured mounted user/session/workspace/reference. Unknown Start, browser or Finalize acknowledgements retain the handle and use read-only recovery. No-auth is an explicit response with zero browser calls. Provider-specific status and error policy stay separate from MCP.
4. Route MCP shared OAuth and Composio shared OAuth through one Electron browser-opening mechanism. Each adapter owns its state format and fixed backend route. Validate the current main frame, actual cookie session, exact waiting summary, target, URL and deadline around awaits and browser acknowledgement. Detect navigation and cookie A/B/A transitions; coalesce concurrent identical calls only while in flight. Preserve personal MCP behavior.
5. Accept the gate with actual HTTP/auth/SQL/provider fixtures, React races and controlled Electron boundaries, then production build, TypeScript, focused lint and graph change review. Test missing Start acknowledgement/early Cancel, No-auth, callback privacy, wrong sessions, lost browser/Finalize acknowledgement, current revisions and original MCP regressions. Run migrations repeatedly against an acknowledged isolated native database and verify cleanup. Controlled fixtures do not establish external Composio consent or production acceptance.
