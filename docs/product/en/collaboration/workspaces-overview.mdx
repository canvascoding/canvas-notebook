# Workspaces Overview

A workspace is the primary boundary for Canvas content and activity. It identifies a file root, its owning scope, the current user's permissions, and the context used by agents, Studio, automations, to-dos, brand profiles, and collaborative editing.

## What belongs to a workspace

When you select a workspace, Canvas scopes operations such as:

- browsing, editing, uploading, and sharing files;
- starting agent sessions and resolving their file context;
- saving Studio outputs;
- creating workspace to-dos and assignments;
- applying brand guidance and document styling; and
- showing active collaborators and agent edits.

Sessions keep a workspace reference and a runtime snapshot. Changing the active workspace in the interface does not silently move an existing session to a different file boundary.

## Permission model

Canvas resolves explicit capabilities rather than relying only on a role label: read, write, delete, create public links, manage the workspace, and run an agent. Features should be unavailable when the current workspace permission does not allow them.

Workspace status also matters. Active workspaces can be selected; archived, disabled, and recovery-locked workspaces are not normal operating targets.

## Start with the smallest scope

Use a personal workspace for private drafts, a team workspace for a durable internal group, and a project workspace for bounded project membership, including carefully limited external participants. Use the organization workspace for shared material governed through organization-level membership.
