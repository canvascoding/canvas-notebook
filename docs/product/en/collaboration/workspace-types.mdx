# Workspace Types

Canvas supports four workspace types. The type determines ownership, membership management, and the way permissions are resolved.

## Personal

A personal workspace belongs to one user. Its owner can read, write, delete, create public links when sharing is allowed, manage the workspace, and run agents. Personal workspaces do not have member lists.

## Organization

The organization workspace is shared through organization-level user permissions. Owners and administrators can manage it; other active organization users receive the capabilities granted by organization policy. Manage its access from organization users, not the workspace member screen.

## Team

A team workspace is an organization-scoped shared area with its own member list. Managers can grant read, write, and manage capabilities to eligible organization users. Team features may depend on instance configuration and license entitlements.

## Project

A project workspace connects a workspace to a project and has project-specific members. Read, write, and manage permissions can be assigned separately. External organization users are restricted to project workspaces and can create public links only when they also have project management capability.

## Status and conversion

Workspaces can be active, archived, disabled, or recovery-locked. Treat a type change as an access-model change: review memberships, agent sessions, automations, public links, and output destinations before and after conversion.

For the effective capability details, see [Workspace members and roles](/docs/collaboration/workspace-members).
