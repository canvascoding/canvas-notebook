# File and Folder References in Chat

Use an `@` reference when the task depends on a file or folder that already exists in the active workspace. A selected reference gives the request an explicit path instead of relying on the agent to guess which document you mean.

## Add a reference

Type `@` in the composer and search the available workspace entries. Select the intended file or folder, then explain what the agent should do with it.

```text
Compare @research/interviews.md with @brief/audience.md and add only
the supported findings to @drafts/personas.md.
```

The reference picker can also surface other supported reference types, such as enabled skills. The active agent's capabilities and workspace access determine what can be selected and used.

## Reference versus attachment

A workspace reference points to an existing file in place. A chat attachment uploads a new copy into the user-upload intake area. Use a reference for durable project material and an attachment for a file that currently exists only on your computer.

## Keep paths stable

References are strongest signals, not permanent locks. If a file is moved, deleted, or replaced before the agent reads it, the task can fail or use stale context. Use precise names, keep related material in one project folder, and verify the output path after the run.

## Files below an answer

After a run, the chat collects files confirmed by completed workspace read, write, edit, and patch tools into one file section. It shows up to three results directly. Expand the section to see the remaining files; larger expanded lists include a search field and scroll within a bounded area.

Each result indicates whether the file was created, changed, left unchanged, or a change was proposed. “Change proposed” describes the tool's result at that time; use the existing file review widget to inspect the current proposal and accept or reject it.

Documents the agent read appear in a separate, initially collapsed group. Reading a document does not necessarily mean that the answer cites or relies on it. The same file appears only once per run, with a change taking precedence over a read.

Selecting a file opens it in its workspace with the current access checks. A file that has since moved or been deleted may no longer open. Studio outputs outside the workspace continue to use their media previews.

File sections use tool results, not guessed filenames in answer text. Explicit Markdown links still work, including in older conversations. Inline code and example paths remain text. Older conversations can show file sections when their saved tool metadata is sufficient; the app does not reconstruct missing references from prose.

For exceptionally large tool batches, the UI retains up to 500 references per tool and reports when additional references were omitted. The original tool output remains available through its existing output viewer when retained.
