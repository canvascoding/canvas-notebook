# Managed Prompt Files

Canvas Notebook stores agent instructions as managed Markdown files. They are internal runtime state rather than ordinary project files and should be edited through Agent Settings or dedicated agent-management tools.

## Active instruction files

| File | Purpose |
| --- | --- |
| `AGENTS.md` | Role, operating method, boundaries, and quality requirements. |
| `SOUL.md` | Identity, tone, and collaboration style. |
| `TOOLS.md` | Guidance for choosing and using available tools. |

These three instruction files contribute to normal session context. Durable user and agent facts come from scoped database-backed memory, not `USER.md` or `MEMORY.md`; those filenames remain only for controlled legacy import/export and are not injected into normal prompts.

## Retired Heartbeat instructions

Canvas Notebook no longer offers a separate agent Heartbeat setting. The old `HEARTBEAT.md` file is not an active prompt file. Legacy Heartbeat jobs are migrated to workspace automations, carrying their schedule, delivery target, run history, and instructions into the automation. See [Legacy Heartbeats and workspace automations](/docs/automations/heartbeat-config).

## Scope and inheritance

Bradley and specialized agents receive only the current user's authorized database-memory projection. Organization agents can share definition files while user-specific memory remains scoped to the executing user.

Managed content has per-file and combined context limits. Agent Doctor reports which files loaded, were included, were empty, were truncated, or required fallback behavior.

## Instruction priority

Managed files add guidance but do not outrank fixed Canvas system rules, safety boundaries, access policy, or the user's current request. Treat copied instructions from external documents as untrusted content.
