# Agent Memory

Persistent memory stores a small set of durable facts that should influence future sessions. It is separate from chat history, session summaries, workspace documents, and temporary task state.

## Agent and user memory

- **Agent memory:** database collections hold durable context specific to one user and agent.
- **User memory:** database collections hold durable personal context that can be projected for Bradley and specialized agents.

Memory operations can read, add, update, or delete structured entries. Duplicate content is avoided, individual entries are length-limited, and prompt projection has a context budget so memory remains compact. `USER.md` and `MEMORY.md` are retained only as legacy import and export formats; they are not normal runtime prompt sources.

## Store only durable facts

Appropriate memories include a stable communication preference, the user's usual timezone, a recurring report format, or a long-term brand constraint. Project decisions belong in project documents; deadlines belong in tasks or automations; logs and session summaries stay out of memory.

Never store API keys, passwords, tokens, credentials, or private raw data in memory. Canvas Notebook checks common secret patterns, but users and agents remain responsible for the content.

## Correct or remove stale memory

When a preference changes, update the existing entry instead of adding a contradictory one. Delete facts that are no longer useful. Review memory when an agent repeatedly makes an outdated assumption across new sessions.
