# Managing Multiple Inboxes

Email shows the signed-in user’s personal accounts and the shared mailboxes assigned to workspaces they can access. The selector groups Personal and Workspaces and displays the selected sender address and workspace name. Credentials and policies remain separate for each account.

## Switch accounts intentionally

Select the account before searching, reading, composing, or using an email agent tool. Shared operations identify both the account and its mailbox workspace, which can differ from the workspace used for chat or files. The app remembers a valid selection for the current user and session. Losing access clears the old content and requires an explicit selection; it does not silently change the sender. When an automation or agent workflow can access several accounts, name the intended account rather than relying on whichever one was most recently active.

## Choose a primary account

The primary personal account is the default when an operation does not specify another active account. Only an active personal account can be primary. If the primary account is disconnected, Canvas promotes another active personal account when available.

Primary does not mean globally unrestricted. The account's send policy still applies, and a send-only SMTP account still cannot provide an inbox without IMAP.

## Keep boundaries per account

A client mailbox and an internal company mailbox should not share a broad implicit policy. Configure permitted senders and recipients separately. Review account display names so the composer makes the active identity obvious.

Before sending, verify From, To, CC, subject, and thread. Reply-all excludes the sending identity; personal mail can also exclude the user’s other connected addresses. Always review the final recipient list. Switching accounts while a compose draft is open asks before discarding it.
