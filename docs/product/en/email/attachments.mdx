# Working with Email Attachments

The composer can attach a file from the active workspace or upload a new file from your computer. Keep the source and delivery format explicit so the recipient receives the intended artifact.

## Add a workspace file

Open Attachments, search the active workspace, and select the file. This keeps the attachment tied to a durable project source. Markdown files can be delivered in their original plain-text format or rendered to PDF for a recipient who should see the formatted result.

## Upload a local file

Use the Upload tab for material that is not in the workspace. Uploaded email files are temporary compose inputs; place important sources in the workspace separately when they must remain part of the project record.

## Limits and formats

A message can include up to 25 attachments with an estimated encoded transfer budget of 20 MB. Email encoding increases transfer size beyond the raw file size, so the interface reports usage against the effective limit.

Images can also appear inline when the HTML body references their content ID. Canvas removes unreferenced inline items before sending. Common document, image, text, archive, spreadsheet, and PDF types receive appropriate MIME information; unknown types use a generic binary type.

## Review before sending

Open each attachment, verify the version, remove obsolete files, and confirm that confidential material belongs with every recipient. An AI-drafted message does not validate the attachment contents or access rights.
