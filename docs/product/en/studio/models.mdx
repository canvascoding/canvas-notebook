# Products, Personas, and Styles

Studio models package a name, description, thumbnail, metadata, and one or more reference images into a reusable library item. They reduce repeated uploads and make reference intent clearer across generations.

## Choose the correct model type

- **Product:** preserves a physical item, packaging, materials, or branded object.
- **Persona:** represents a recurring approved character or person reference.
- **Style:** communicates lighting, color, texture, illustration, camera, or art direction.

A model can contain images uploaded directly or imported from a URL. Order the strongest, most representative views first and remove references that conflict with the approved identity.

## Build a useful product model

Include several clean angles, a clear label or mark, and important construction details. Use the description for facts that an image may not show, such as material or required color. Do not add lifestyle images that obscure the product when the model's primary job is geometry consistency.

## Build personas responsibly

Use only images with suitable rights and consent. Describe stable visual attributes without turning sensitive personal data into generation metadata. A persona model improves continuity but does not guarantee identity fidelity.

## Keep style separate from subject

A style library should represent visual treatment, not a specific product that might accidentally appear in every output. In prompts, state which properties each selected model should influence.
