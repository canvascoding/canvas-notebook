# Email

Canvas Notebook brings email into the same workspace as files, agent chat, to-dos, and automations. Connected accounts can be used to read inboxes, inspect messages, work with attachments, prepare drafts, and support agent-assisted communication.

Email is separated from system notifications. A connected inbox represents a user-facing mailbox, while system email is an administrative configuration used by the application for service messages and notifications.

## Core capabilities

- Connect and manage multiple email accounts.
- Use Gmail or configured SMTP/IMAP connections.
- Choose the main account for a workflow.
- Read inbox messages in the Notebook interface.
- Create drafts and replies with rich HTML content.
- Review and include attachments.
- Pass the active email context into agent chat.
- Apply sending policies and guardrails.
- Use email notifications for assigned to-dos where configured.

## A representative workflow

Open a client message, review its attachments, and ask the agent to prepare a concise reply based on the current project brief. Compare the draft with the original email, confirm the sender and recipient list, check every attachment, and send only after the message is ready.

If the reply creates work for someone else, add a to-do or follow-up rather than leaving the obligation hidden in the inbox.

## AI-assisted drafting

The agent can use the active message and workspace context to help summarize a thread, extract requested actions, or draft a response. This is most useful when the relevant project documents are already organized in the active workspace.

An AI-generated draft is not proof that names, dates, prices, recipients, or commitments are correct. Treat the draft as editable work and retain human review for external communication.

## Guardrails and account safety

Email credentials are stored through protected account and secret services. Do not paste passwords or access tokens into chat or Markdown files.

Sending policies can restrict how mail is prepared or delivered. Always verify the active account, sender identity, recipients, quoted history, and attachments. A wrong recipient can expose project information even when the message text is otherwise correct.
