# Managing API Keys and Secrets

Credentials should be configured in the narrowest scope that owns the connection. Never paste API keys into Markdown notes, prompts, skill packages, plugin manifests, MCP configuration, screenshots, or chat messages.

## Encrypted environment storage

Canvas can encrypt stored integration and agent environment values with AES-256-GCM when the corresponding master key is configured:

- `INTEGRATIONS_ENV_MASTER_KEY`
- `AGENTS_ENV_MASTER_KEY`

Without a master key, scoped environment files still use owner-only file permissions but their values are stored as plain text. Set stable master keys through the deployment environment and include them in the secure backup plan. Losing a key makes encrypted values unreadable.

## Safe configuration pattern

1. Create a credential at the provider with the smallest practical permission set.
2. Store it through the relevant provider, connection, or environment settings.
3. Reference it by environment variable from MCP or plugin configuration.
4. Test with a low-risk operation.
5. Record the owner, purpose, scope, and rotation date outside the secret value itself.

## Rotation and removal

Rotate a credential immediately if it appears in a document, log, archive, package, or chat. Update Canvas, restart affected runtimes, verify the new value, and revoke the old credential at the provider. Disconnecting a UI integration does not guarantee that every provider token has been revoked.

Backups that include runtime data may contain encrypted or plain credential material. Protect them like production secrets and restore master keys separately through secure deployment configuration.

## Package safeguards

Custom skill imports reject common secret files and private-key formats. MCP configuration rejects literal secret-like values. These checks are defense in depth, not a substitute for reviewing third-party instructions and scripts.
