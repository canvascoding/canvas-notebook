# Scheduled Automations and Webhook Triggers

Canvas Notebook runs recurring work as workspace automations. A scheduled automation starts at a configured time; a webhook-triggered automation starts when an external system sends an event.

| | Scheduled automation | Webhook-triggered automation |
| --- | --- | --- |
| Trigger | A one-time or recurring schedule. | An event sent by an external system. |
| Instructions | The automation prompt. | The automation prompt plus event data. |
| Configuration | Automations. | Automations and the external trigger setup. |
| Scope | The selected workspace and configured output or delivery. | The selected workspace and event-triggered run. |
| Typical use | A daily report or weekly review. | Process a new order, form, or system event. |

## Choose a scheduled run when

- the work should start at a predictable time;
- the prompt can name its inputs, output, and boundaries;
- you want to run it manually before depending on a schedule.

## Choose a webhook when

- another system owns the event that should start the work;
- the event data should be available to the automation during the run;
- the workflow needs to respond to activity rather than a clock.

The separate agent Heartbeat configuration and `HEARTBEAT.md` workflow are retired. Existing Heartbeat jobs are migrated into scheduled workspace automations; see [Legacy Heartbeats and workspace automations](/docs/automations/heartbeat-config).

Keep externally triggered work narrow and treat webhook payloads as untrusted input. For scheduled work, test the prompt manually and inspect the run before relying on unattended execution.
