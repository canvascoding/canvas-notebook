# Running an Automation Manually

A manual run uses the saved job definition immediately and records `manual` as its trigger. It is the safest way to validate a new or changed automation before unattended execution.

## Validate before the first scheduled run

1. Save the job as paused while you review its workspace, agent, provider readiness, context paths, output, and delivery.
2. Choose a next scheduled time far enough ahead to finish the test first.
3. Activate the job when you are ready to test it. Paused jobs cannot be run manually.
4. Choose Run Now and watch the run status until success or failure.
5. Open the result session and any created files.
6. Review delivery and the event log.
7. Correct the job and test again; pause it if the scheduled run should not proceed yet.

The manual action does not rewrite the saved schedule or next recurring time. Activating the job does make its schedule eligible to run, so leave enough time to inspect the manual result before the next scheduled occurrence.

## Avoid duplicate side effects

Running twice can create duplicate drafts, files, public links, or external actions unless the prompt is idempotent. Check the previous run before retrying. For a test involving email or an external channel, configure a safe recipient or silent delivery until the workflow is approved.

## Use the saved definition

If the one-time task is materially different, create a normal chat request or a separate job. Temporarily rewriting a production automation for an unrelated run makes its history harder to interpret and risks leaving the wrong definition active.
