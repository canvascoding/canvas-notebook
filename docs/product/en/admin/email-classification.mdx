# Administering Email Preparation

An instance administrator manages Email preparation in Settings → System Email. It starts disabled and applies centrally to everyone on the server, including personal and shared work mailboxes. Mailbox permissions and sender rules continue to apply. It is separate from the system SMTP sender used for notifications.

## Configure before enabling

1. With Canvas managed, select an approved decision model. Control Plane manages providers, credentials and pricing centrally; no local provider key is required. Existing own-provider configurations remain available. Open Provider and configuration to change deployment mode.
2. For an own provider, select TypeSafe Jev, OpenAI Decisions or a System One compatible service and its model there. Set the endpoint for a compatible service. Save the provider key in [Settings → Secrets](/settings?tab=secrets) under the System scope. The preparation card needs only the credential name, such as `TYPESAFE_API_KEY`, never the key value. Personal or organization keys do not configure this server feature.
3. Choose Test draft. It evaluates a fixed synthetic email and is available while preparation is disabled and before saving your edits. It does not read a real mailbox.
4. Set Enable for everyone and choose Save settings. Confirm the saved activation and processing status.

OpenAI Decisions uses `gpt-6-luna`, the fixed OpenAI endpoint and the System Secret `OPENAI_API_KEY` by default. The native Decisions service is in public beta. A declined assessment has a separate error state; review the criteria or select another provider.

An explicitly allowed private-network compatible endpoint can be configured without authentication by leaving the credential name empty. A missing named key remains a configuration error.

Users get Focus by default when enabled, with a saved Classic choice respected. Changing the view does not disable background preparation. Disabling centrally returns users to Classic and pauses new model evaluations while keeping stored assessments for later use.

## Adjust details when necessary

Preparation selects all unread Inbox emails without an age limit, plus other Inbox emails within the lookback, independently for each mailbox. Advanced settings contains the daily attempt budget, concurrency, timeout and synchronization interval. The additional lookback for read emails is at most 30 days. The historical batch size limits new assessments per scan; further scans continue the remaining eligible backlog. Existing assessments remain available after reading. Mailbox context and category criteria describe how personal and shared work mail should be evaluated. Decision thresholds leave intermediate scores visible for review.

A successful sample checks connection and response compatibility. It does not validate accuracy or calibrate probabilities. Automatic suspected-spam sorting requires a separately evaluated provider/model/schema profile. The card does not offer a checkbox to declare that evaluation complete.

## Read status and recover

Activation and processing status are separate. A provider/key problem or exhausted daily budget can pause new preparation while saved assessments remain usable. Index coverage can also be incomplete or failed. Processing details shows captured, prepared, waiting and failed counts and the available daily budget; these are operational counts rather than an accuracy report.

In managed mode, check the instance connection, approved models, organization entitlement and credits in Control Plane. A temporary outage keeps saved assessments visible while new preparation waits. Pricing changes do not trigger new assessments. An actual model change reassesses only the selected backlog and resets previous spam-validation approval.

For missing or unreadable own-provider credentials, check System Secrets and test the draft again. For an email connection problem, repair the affected mailbox. Users can select that mailbox in Classic while you investigate. Unknown status should be retried before interpreting it as an empty workload.

If another administrator saves first, your edits remain in place and saving is blocked. Reload saved configuration deliberately replaces your draft with the latest settings. A Secrets update refreshes credential status without replacing unsaved configuration edits.
