# Document API

**Unreleased preview.** This reference describes the development API. It is not yet a publicly deployed API or a released SDK. Availability depends on the installed Canvas version, enabled native-document features, and the tools authorized for your connection.

Use this sequence: search for a document, keep its stable identity, read its full version, then submit a guarded edit. A path or a Markdown file hash is not a native document version. Keep credentials outside document content and application logs.

## Transports and authorization

| Transport | Authentication | Available document operations |
| --- | --- | --- |
| REST on your Notebook origin | An actual Better Auth user session, using its cookie or issued Session Bearer | Search, read by ID, edit, and edit status |
| Direct MCP at `/mcp` | OAuth 2.1 authorization code with PKCE and a token issued for this MCP resource | Search, read by ID, native Markdown create/import, edit/status, and explicitly enabled native Copy |

These credentials are different. An MCP resource access token is not a REST Session Bearer. Do not copy an MCP token into a REST request or construct a session from a user ID. All operations check current session, workspace access, and relevant policy; knowing a document ID, version, cursor, or operation ID grants no access.

REST requests send `Content-Type: application/json` with the actual user-session cookie or `Authorization: Bearer` followed by the issued Session Bearer. Use the normal supported sign-in flow to obtain that session. Signing out its source session revokes subsequent uses; a copied Bearer is not an independent long-lived API key.

For MCP, enable the server, opt the workspace into access, obtain the user's grant, and enable each required tool. Creation, import, and editing require explicit tool enablement. Request only the OAuth scopes needed by your client:

| Tool | Scope |
| --- | --- |
| `list_workspaces` | `workspace:list` |
| `search_knowledge` | `knowledge:search` |
| `read_knowledge_source` | `knowledge:read` |
| `create_knowledge_source`, `import_knowledge_file`, `edit_knowledge_source` | `knowledge:write` |
| `copy_knowledge_source` (explicit opt-in) | `knowledge:write` |

Search permission does not grant full-read permission. Write scope does not grant a separate read scope. Create/edit also require the current workspace read/write and agent-access permissions enforced by the MCP service. Edit status uses the same write tool and authorization as editing, even though observing status does not apply a change.

Use the instance's advertised protocol and the schemas returned by `tools/list`. The current modern protocol is `2026-07-28`: discover it with `server/discover`, then use `tools/list` and `tools/call`. Do not send a legacy `initialize` handshake under a modern protocol header. Use a compatible MCP transport client rather than assuming every HTTP response is plain JSON.

Examples below show REST JSON or MCP `tools/call` parameters. JavaScript variables such as `workspaceId`, `hit`, and `page` stand for actual earlier responses; they are not additional request fields or SDK methods.

## Search progressively

REST: `POST /api/documents/search`.

```json
{
  "apiVersion": 1,
  "workspaceId": "your-workspace-id",
  "query": "Target",
  "scopePath": ".",
  "limit": 8
}
```

Equivalent MCP parameters:

```javascript
{
  name: "search_knowledge",
  arguments: {
    api_version: 1,
    workspace_id: workspaceId,
    query: "Target",
    path: ".",
    max_results: 8
  }
}
```

The query is a case-insensitive literal, not a regular expression. It needs at least two Unicode code points and at most 200 UTF-8 bytes. `scopePath` is a workspace-relative path scope; `.` means the workspace. Hidden path segments beginning with a dot are excluded from the searched corpus.

Each hit contains `document`, `currency`, `matchedIn`, and a bounded `snippet`. `document` includes the stable `documentId`, `lineageId`, lifecycle generation, representation, schema version, path/title, full `version`, and separate `metadataVersion`. `matchedIn` names the matching title, path, or content fields.

The first slice searches visible, initialized native Yjs text documents. It does not search physical-only files, Excalidraw scenes, or PDF bodies. Read the returned `coverage`: ranking is within each scan window, remote live coverage is always `unknown`, and `globalCurrentContent` is `not_certified`. An empty page does not establish that the entire workspace has no matches.

The default result limit is 8 and the accepted range is 1–25. A scan window examines at most 8 candidates; the whole JSON page is capped at 12,000 UTF-8 bytes and each snippet at 512 bytes. Exclusions and output limits can produce fewer hits. Continue while `nextCursor` is non-null, including after an empty page. Send its exact value with the same query and scope. Do not decode or modify the cursor. `SEARCH_CORPUS_CHANGED` means start a fresh search; it is not an instruction to reuse an old cursor automatically.

## Read by stable ID and full version

REST: `POST /api/documents/read`. Required fields are `apiVersion: 1`, `workspaceId`, and `documentId`. Optional fields are `format`, `includeEditTargets`, `expectedVersion`, `maxBytes`, and `cursor`.

MCP uses `read_knowledge_source` with these parameters:

```javascript
{
  name: "read_knowledge_source",
  arguments: {
    workspace_id: workspaceId,
    document_id: hit.document.documentId,
    expected_version: hit.document.version,
    format: "native",
    max_bytes: 65536
  }
}
```

Use `document_id` for this branch; do not combine it with a legacy path selector. This MCP read branch does not take `api_version`. REST uses camelCase names, including `expectedVersion` and `maxBytes`.

| Format | Meaning |
| --- | --- |
| `native` (default) | JSON with `bodyVersion`, `representation`, and native `content`; preserves native structure |
| `text` | Semantic plain text for inspection and matching |
| `markdown` | Explicit Markdown export; may fail with `DOCUMENT_FORMAT_UNAVAILABLE` when it cannot faithfully represent the native content |

Supported text representations are `plain_text`, `tiptap_xml`, and `tiptap_blocks`. Native and text reads do not require an existing Markdown projection.

The response contains `document`, `currency`, `projection`, `format`, `mediaType`, `encoding`, `fragment`, `byteOffset`, `byteLength`, `totalBytes`, `nextCursor`, and `complete`. The fragment is UTF-8 text; offsets and lengths count bytes. Default page size is 65,536 bytes, with an accepted range of 4–262,144 bytes. The response envelope is additional to this fragment limit.

For a complete body, concatenate fragments in order until `nextCursor` is null. Parse native JSON only after concatenating all fragments. On subsequent pages keep the same document, format, edit-target option, and `expectedVersion`, and pass the exact cursor. Each page is freshly authorized and checked against the content, metadata, and encoded-body binding. If a version or scope conflict occurs, discard the partial body and start a new read; never combine pages from different observations.

`document.version` is an opaque full native content token, including deletion evidence. `metadataVersion` separately identifies path/title metadata. `currency.observedDurable` distinguishes the observed body from a durable observation; `durableVersion` and `durableSequence` describe persistence. `projection.status` reports `current`, `pending`, or `unavailable` independently. A matching visible text string is not a substitute for these fields.

## Create or import native Markdown through MCP

There is no create endpoint in the REST V1 surface documented here. Use `create_knowledge_source` for complete UTF-8 Markdown or `import_knowledge_file` for a host-provided file reference. Supply `api_version: 1` to request the native result explicitly.

```json
{
  "name": "create_knowledge_source",
  "arguments": {
    "api_version": 1,
    "workspace_id": "your-workspace-id",
    "path": "notes/example.md",
    "idempotency_key": "create-example-001",
    "content": "# Example\n\nOAuth edit target 😀.\n\nKeep final tail.\n"
  }
}
```

Creation never overwrites an existing document. Native V1 requires enabled native Markdown creation and a `.md` or `.markdown` destination. Text is limited to 512 KiB of UTF-8. The native result has exactly these top-level fields:

```typescript
{
  apiVersion: 1;
  operationId: string;
  outcome: "created" | "already_created";
  document: NativeDocumentRefV1;
  currency: DocumentCurrencyV1;
  projection: DocumentProjectionV1;
}
```

`document`, `currency`, and `projection` use the same shapes as ID reads. Keep the returned identity and use `document.version` as the first read's expected version. Omitting `api_version` retains the older file-receipt response; that response is not the V1 native result. A retained physical/legacy creation is not converted by requesting V1: expect `MCP_INGEST_NATIVE_DOCUMENT_REQUIRED`.

For import, replace `content` with the host's actual `file` object:

```javascript
{
  name: "import_knowledge_file",
  arguments: {
    api_version: 1,
    workspace_id: workspaceId,
    path: "notes/imported.md",
    idempotency_key: "import-example-001",
    file: {
      download_url: hostFile.download_url,
      file_id: hostFile.file_id,
      mime_type: "text/markdown",
      file_name: "imported.md"
    }
  }
}
```

`download_url` must be a genuine temporary HTTPS file reference supplied by the host, not a URL invented by an agent. `file_id` is required; MIME type and file name are optional. Network and content validation still apply. When the existing completion and destination can be confirmed, a completed same-key import retry returns without downloading a replacement URL. A changed original document can instead produce `MCP_INGEST_DESTINATION_CHANGED`; completion is not permission to overwrite it. An unfinished recovery may still need the original source bytes. Preserve the file identity and MIME selection on retries.

## Edit native content

REST: `POST /api/documents/edit`.

```javascript
{
  apiVersion: 1,
  workspaceId,
  documentId: page.document.documentId,
  expectedVersion: page.document.version,
  idempotencyKey: "edit-example-001",
  patch: {
    kind: "native_text_replace",
    edits: [{ oldText: "OAuth edit target", newText: "MCP changed target", expectedOccurrences: 1 }]
  }
}
```

MCP uses the same patch with explicit action and snake_case outer selectors:

```javascript
{
  name: "edit_knowledge_source",
  arguments: {
    api_version: 1,
    action: "edit",
    workspace_id: workspaceId,
    document_id: page.document.documentId,
    expected_version: page.document.version,
    idempotency_key: "edit-example-001",
    patch: {
      kind: "native_text_replace",
      edits: [{ oldText: "OAuth edit target", newText: "MCP changed target", expectedOccurrences: 1 }]
    }
  }
}
```

`expectedVersion` is required and is checked against the full native state at the actual write. Do not replace it with a path, Markdown SHA, state vector, metadata version, or text excerpt. The request has no actor/session fields; the transport supplies current authority. Unknown fields or malformed supplied native-version selectors are rejected rather than falling back to legacy editing.

`native_text_replace` matches exact visible text within actual native text targets. `oldText` must be nonempty; `newText` may be empty. `expectedOccurrences` defaults to 1 and binds the intended match count. It is not a regex or an unrestricted replace-all. The optional `blockId` restricts a compatible block document. A match cannot be assumed to span separate native text targets.

### Guarded block operations

For `tiptap_blocks`, read `format: "native"` with REST `includeEditTargets: true` or MCP `include_edit_targets: true`. The option is false by default and is rejected for other formats. It does not make XML/plain representations structural block documents. The reconstructed native body then includes bounded `editTargets` alongside `content`.

Each target has `id`, `type`, `parentId`, `beforeId`, `attrs`, `subtreeHash`, and `placementHash`, plus `tableOperationTarget` when applicable. These guards belong to that exact native read/version. Targets omit duplicated text and private operation data. The opt-in is limited to 512 targets and 64 KiB of target metadata, with tighter native source budgets; it can reject a document that an ordinary read accepts.

Use `patch.kind: "native_blocks"` and its `operations` array. Copy the actual target guards; do not derive them by hashing displayed JSON.

| Operation `kind` | Required fields beyond `kind` |
| --- | --- |
| `move_block` | `blockId`, `placementHash`, `parentId`, `beforeId` |
| `delete_block` | `blockId`, `subtreeHash` |
| `insert_blocks` | `parentId`, `beforeId`, `blocks` |
| `format_block` | `blockId`, matching `beforeAttrs` and `afterAttrs` |
| `format_text` | `blockId`, `subtreeHash`, `from`, `to`, `mark`, `enabled`; `href` only when enabling a link |
| `table_operation` | `cellId`, `subtreeHash`, `action`; obtain the first two from the returned `tableOperationTarget` |

Use null `parentId` for the root and null `beforeId` for the end of that parent's children. Formatting attributes support one matching attribute per operation: heading `level`, task `checked`, ordered-list `start`, or code `language`. Marks are `bold`, `italic`, `strike`, `code`, or `link`. Table actions are row/column insertion, deletion, movement, table deletion, and alignment actions enumerated by the live tool schema. Native schema, URI, text-range, placement, and grapheme checks still apply.

For example, after selecting two actual root-level targets from the complete native read, this patch moves one before the other. Submit it with that read's full version and a new caller key for this distinct intended move:

```javascript
{
  kind: "native_blocks",
  operations: [{
    kind: "move_block",
    blockId: movingTarget.id,
    placementHash: movingTarget.placementHash,
    parentId: null,
    beforeId: beforeTarget.id
  }]
}
```

An edit request is capped at 512 KiB of UTF-8 JSON, 32 text edits/total text targets or 32 block operations, and 256 inserted root blocks. Deep or excessively complex JSON is also rejected. The whole patch is prepared and validated before applying its native change.

## Idempotency and operation status

Create/import and edit keys contain 8–128 characters matching `[A-Za-z0-9][A-Za-z0-9._:-]{7,127}`. Generate a key once for the intended request and retain it. Retry that exact request with the same key, including the original expected content version and patch. Reusing a key for different content, a different target, or a changed patch is a conflict; changing the key to resolve an unknown outcome risks a second change.

For MCP retries, retain the same user, client, and workspace. A renewed actual session can authorize a retry/status call without changing the operation's original attribution. Expired or revoked credentials remain rejected. A key or historical session identity never authorizes recovery by itself.

Edit/status returns `apiVersion`, `operationId`, `state`, `document`, `effect`, `persistence`, `projection`, and `history`:

| Field | Interpretation |
| --- | --- |
| `state` | `pending`, `confirmed`, `conflict`, or `failed`; only `confirmed` has confirmed persistence |
| `document` | Historical native identity, representation, and generation; no invented current path/title/reference |
| `effect` | Historical `applied`/`no_change`, `beforeVersion`, `afterVersion`, and `appliedAt`, or null |
| `persistence` | `confirmed` with recorded sequence/time, or `unconfirmed` with null confirmation fields |
| `projection` | Recorded `checkpointed` evidence or `unconfirmed`; not a current filesystem-availability check |
| `history` | `captured`, `unconfirmed`, or `over_limit`, with a revision ID only when captured |

The whole result is bounded to 8 KiB. Do not interpret a pending effect as confirmed durability, or a historical `afterVersion` as today's document version. A fresh ID read may report later peer edits; read with `effect.afterVersion` only when you need that exact version and handle a conflict honestly.

Read edit status through REST `POST /api/documents/edit/status` with exactly `apiVersion: 1`, `workspaceId`, and `operationId`, or through the same MCP edit tool:

```javascript
{
  name: "edit_knowledge_source",
  arguments: {
    api_version: 1,
    action: "status",
    workspace_id: workspaceId,
    operation_id: editResult.operationId
  }
}
```

Status observes the recorded operation without applying or reconciling it. It requires fresh write authorization for the same transport owner. Preserve an `operationId` returned with an error and use it for a permitted status observation. This status endpoint covers native edits; it is not a general create/import status endpoint.

## Native Copy through MCP

`copy_knowledge_source` is a development tool with an independent explicit opt-in; it is off by default. Preview, Apply and Recover additionally require the native feature gate. Every action checks the current client/user and access to both workspaces: source read access and destination write access. A renewed session for the same authorized client/user can inspect or recover its existing operation; an operation ID grants no access by itself.

Start with a Preview using the actual workspace IDs and canonical workspace-relative paths:

```javascript
{
  name: "copy_knowledge_source",
  arguments: {
    api_version: 1,
    action: "preview",
    source_workspace_id: sourceWorkspaceId,
    destination_workspace_id: destinationWorkspaceId,
    selections: [{ source_path: "notes/a.md", destination_path: "copies/a.md" }],
    rename_on_collision: true
  }
}
```

The response contains `apiVersion: 1`, `action: "preview"` and the full public V4 `preview`. Preserve its `planId`. For each original selected root, find its exact `sourcePath` entry in `preview.pathMappings` and retain the resolved `destinationPath`, in the original selection order. The mappings also contain descendants; do not submit every mapping as a selection.

Persist a caller-selected operation ID and the exact Apply request before sending it. Use the resolved root paths and set `rename_on_collision: false` or omit that field. Apply and Recover reject `true`; a retry must retain the already chosen destination name.

```javascript
{
  name: "copy_knowledge_source",
  arguments: {
    api_version: 1,
    action: "apply",
    source_workspace_id: sourceWorkspaceId,
    destination_workspace_id: destinationWorkspaceId,
    operation_id: callerOperationId,
    plan_id: previewResult.preview.planId,
    selections: resolvedRootSelections,
    rename_on_collision: false
  }
}
```

Operation IDs contain 16–128 ASCII characters, start with a letter or digit, and otherwise allow letters, digits, `_` and `-`; a caller-generated UUID fits. A plan ID is the returned 64-character lowercase hexadecimal value. The tool never generates a replacement operation ID for a client.

Apply/Recover returns `execution`, `copied` paths and `alreadyKnown`. Inspect `execution.status`: `complete`, `needs_recovery` or `failed`. A successful HTTP/MCP response does not imply complete publication. The result supplies no new document IDs; use native search and a returned stable ID/full version when reading a resulting native document.

For a pure status observation send only `api_version`, `action: "status"`, both workspace IDs and `operation_id`. Status does not apply or repair an operation and remains readable, with current authorization, when the native mutation gate is off. `operation.completion.status: "confirmed"` is historical completion evidence; journal labels alone do not prove completion or current file contents. `COPY_STATUS_NOT_FOUND` does not prove that no work occurred and does not authorize a new operation ID.

Explicit Recover uses the exact retained Apply request with `action: "recover"`, including its original operation ID, plan ID and resolved selections. It continues an existing operation only. `COPY_OPERATION_NOT_FOUND` never starts a replacement copy. Keep the original request and ID after `COPY_OUTCOME_UNCONFIRMED`, a transport failure or a late output-size error.

The request is bounded to 65,536 UTF-8 JSON bytes and 1,000 selections; the complete canonical server request, including actual origin data and resolved names, has its own 65,536-byte limit. The entire MCP result envelope, including text, structured content and authorization metadata, is bounded to 1 MiB. Results and previews are not silently clipped.

The current native owner requires an initialized native Markdown graph. Uninitialized physical Markdown in the inspected source or destination graph can produce `COPY_NATIVE_REQUIRED`, even outside the selected roots. This is an open import/rebinding boundary. Do not migrate a read-only source or write its Markdown projection to bypass it. Move/Delete and Python SDK Copy methods are separate pending connections.

## Errors and client handling

REST uses HTTP status codes and a bounded JSON body. Native read/search errors contain `apiVersion: 1`, `success: false`, and `code`. Edit errors can additionally retain `operationId`. MCP tool failures can arrive as `isError: true` with structured error content even when HTTP transport succeeded; also handle transport/protocol errors and OAuth challenges. Creation/import uses its existing ingest error vocabulary, not the edit error envelope.

| Error family | Client action |
| --- | --- |
| `AUTHENTICATION_REQUIRED` / `ACCESS_DENIED` | Obtain genuine current authorization or report the denied access; preserve a supplied recovery ID |
| `DOCUMENT_VERSION_CONFLICT` | Read the current document and reconsider the intended change; do not remove the guard |
| `DOCUMENT_EDIT_CONFLICT` | Resolve ambiguous/missing text targets, stale local guards, overlap, or active composition against a fresh native read |
| `DOCUMENT_IDEMPOTENCY_CONFLICT` | Inspect the original request/key; do not silently assign a new key |
| `DOCUMENT_EDIT_UNSUPPORTED` / `DOCUMENT_FORMAT_UNAVAILABLE` | Use a supported native operation/format without rewriting through disk |
| `DOCUMENT_BUSY` / scope changed | Stop this attempt; keep mutation identity and obtain a fresh authorized observation before deciding the next step |
| `EDIT_OUTCOME_UNCONFIRMED` / `READ_OUTCOME_UNCONFIRMED` | Do not infer a committed edit from matching text or blindly replay; retain any operation ID and inspect supported status |
| `DOCUMENT_TOO_LARGE` / search size errors | Reduce the request or selected scope where applicable; do not discard guards or truncate a mutation silently |

Routes can also rate-limit with HTTP 429. REST responses are not cacheable. Application clients should keep error bodies and credentials out of document content, and should not expose tokens or private source text in diagnostics.

## Current boundary

The separately installable [Python SDK development preview](/docs/developers/python-sdk) wraps the search/read/create/import/edit tools described here. It is not yet a released Python package and does not yet wrap the development Copy tool. The internal skill-script FD bridge is a different, package-scoped runtime and is not an external HTTP SDK. Common Move/Delete tools and a PDF-to-native-document creation flow remain pending. Existing file/asset tools have their own schemas and results; do not treat a PDF upload, Markdown output, or physical file receipt as a native document mutation result.
