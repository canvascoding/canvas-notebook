# Uploading and Downloading Files

Uploads bring existing material into the active workspace. Downloads create a local copy of a workspace file so it can be delivered, archived, or edited elsewhere.

## Upload source material

Open the destination folder in the file explorer before uploading. Keep original client assets, reference documents, and generated outputs in separate folders so it is clear which files may be changed.

After an upload finishes, open the file to confirm that the name, type, and contents are correct. Supported formats can be previewed directly; unsupported formats still remain available as workspace files and may be handled by an agent or command-line tool.

Avoid uploading secrets into general project folders. Provider tokens, API keys, and passwords belong in the protected settings for integrations and providers.

## Download a result

Select the file you want to keep or deliver and use its download action. The downloaded file is a snapshot: later workspace edits do not update the local copy automatically.

For Markdown, a download preserves portable plain text. For presentation work, Marp can also produce PDF, PNG, or JPEG slide exports. Other file types are downloaded in their stored format.

## Good transfer habits

- Keep stable source filenames when agents or automations reference them.
- Add a version or date to deliverables when multiple exports must coexist.
- Preview generated files before sending them outside the workspace.
- Treat uploads from unknown sources as untrusted material.
