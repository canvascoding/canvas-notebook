# Embedded Workspace Documents

An embedded workspace document displays content from another Markdown file inside the current note. The source remains a separate file, so several documents can present the same maintained material without copying it.

## Embed with wiki syntax

Add an exclamation mark before a wiki link:

```md
![[approved-brand-voice]]
```

Use an explicit path when two files could have the same name:

```md
![[brand/guidelines/approved-brand-voice.md]]
```

Canvas Notebook resolves the workspace target and renders the referenced Markdown in context. Open the source document when you need to change the embedded material.

Wiki embeds are only for Markdown documents. To display a workspace image, use ordinary Markdown image syntax instead:

```md
![Approved logo](brand/assets/approved-logo.png)
```

Use an ordinary Markdown link for a non-note file that should be opened rather than displayed:

```md
[Download the approved brief](brand/approved-brief.pdf)
```

## When embeds help

Embeds work well for approved boilerplate, product facts, audience definitions, legal language, or a shared status section. A campaign brief can embed the current brand voice while the source remains owned by the brand folder.

Do not create long chains in which one note embeds another that embeds several more documents. Deep nesting makes provenance and missing references harder to understand. Prefer a small number of direct, clearly named sources.

## Missing and sensitive content

If the target is renamed or deleted, the embed can no longer render its source. Use the Document Graph and unresolved-link views to find broken relations.

Before sharing or exporting a document, inspect the rendered result. Embedded content may expose information that is not obvious from the parent file alone.
