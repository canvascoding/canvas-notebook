## Unabhängig nachgewiesene Source-Lücke

Der bisherige Fragment-Effect in [RichMarkdownEditor](../app/components/editor/MarkdownEditor.tsx) hängt nur von Editor, Navigationsrequest und Viewportowner ab. Findet er keine Überschrift, endet er ohne angewandte Anfrage. Eine spätere native Viewprojektion verändert diese drei Identitäten nicht; ein weiterer Versuch fehlt. Die [Blockbindung](../app/lib/collaboration/block-tree-editor.ts) projiziert bei Initialisierung per Microtask und anschließend bei echten Yjs-Transaktionen.

Der äußere MarkdownEditor wartet vor Rich-Mount auf `collaborationDocument.ready`. Ein noch leerer Y.Doc allein erklärt deshalb nicht die reale V13-Chronologie. Die Wiederholungslücke wird mit einem eigenen inneren Komponentenvertrag geprüft; sie ist nicht automatisch die bewiesene Ursache genau dieses Browserfehlers.

Die neue [fokussierte Fixture](../scripts/rich-editor-heading-navigation-ui-test.tsx) verwendet reale React-/Tiptap-Instanzen, einen offline geschlossenen Hocuspocusprovider und echte Yjs-/BlockTree-Fernprojektion. Bei unverändertem Editor, Provider und Request wird eine zuvor fehlende Überschrift eingefügt. Auf dem alten Produkt bleiben Selection 2, Navigationclaims 0 und Scrollanträge 0, obwohl die Überschrift an Position 16 vorhanden ist.
